SECTION 4 — PSM (PATIENT SITE MONTH) METHODOLOGY
================================================================

DEFINITION: Patients per Site per Month — enrollment productivity for one site (or study rollup).

SITE-LEVEL PSM (PRIMARY — Ora Veeva / Buddy):
  site_psm = total_enrolled / site_enroll_months
  site_enroll_months = months from site FSI (First Subject In / FPFV) milestone actual
                       → site LSI (Last Subject In) milestone actual; same month → 1 (never ÷0)
  Dates come from ora_veeva_milestone (milestone__v), NOT study header fields.
  LSO / LPLV = Last Subject Out — end of treatment; NOT the PSM window end unless specified.
  Enrolled: site.no_subjects_enrolled__v, else count from ora_veeva_subject when needed.
  PSM = 0 means activated but never enrolled — exclude from medians; still list the site.
  Null PSM = missing FSI/LSI and/or enrolled — not zero.

STUDY-LEVEL PSM (Ora rollup):
  Prefer median of positive site_psm values for that study.
  Alternate (when only study totals exist): total_enrolled / (n_sites × enrollment_months)
  Do NOT mix study-level grain with site-level PSM in one comparison without labeling.

TRIALHUB STUDY-LEVEL:
  Use th_actual_psm / psm_common when present — do not recalculate from patients/sites unless null.

STUDY-LEVEL PSM: total_enrolled / (n_active_sites × enrollment_duration_months)
Use ACTUAL enrollment duration (FPFV to LPLV), not planned window.

SITE-LEVEL PSM: site_enrolled / site_enroll_months
site_enroll_months = months between site's first and last patient enrolled.
Sites with 0 enrolled → PSM = 0, NOT null. Zero is meaningful (activated, didn't enroll).

~80% NULL PSM RATE — STRUCTURAL FACT:
Approximately 80% of site records have null PSM. This is structural — Veeva only stores
site-level enrollment counts when captured. Null ≠ zero enrollment.
NEVER interpret null PSM as zero performance.
Always report n (sites with non-null PSM) when presenting benchmarks.
Distinguish null (unknown) from zero (enrolled nothing) explicitly.

BLOCK ENROLLMENT EXCLUSION:
Exclude block enrollment studies from startup speed calculations.
Sponsor pre-selects patients before site activation — timing not independently measurable.
Flag: studies where SIV→FSI = 0 days. Confirm with clinical ops when uncertain.

SITES NEEDED FORMULA:
sites_needed = target_enrolled / (planning_PSM × enrollment_months)
buffer = sites_needed × 1.20  [20% standard buffer]
Example: 80 pts / (0.5 PSM × 12 months) = 13.3 → recommend 16 with buffer

  Type: Many-to-many (one org+study can have multiple milestone records: Selected, Contract, IRB, SIV, FSFV)
  CRITICAL: Milestone data is in LONG format — each row is one milestone event, not one site.
  Must pivot to wide format before joining back to fact_site.
  Code:
    raw = pd.read_excel('Mike_Watson_Claude_Report__Site_Level__10Jul2026.xlsx')
    raw['milestone_clean'] = raw['Milestone'].str.extract(
        r'^(Site Selected|Contract Executed|Contract / Budget|IRB/EC Approval|SIV|FSFV|First Subject In)',
        expand=False
    ).replace({'Contract / Budget':'Contract Executed','First Subject In':'FSFV'})
    raw['date'] = pd.to_datetime(raw['Actual Start Date'].combine_first(raw['Actual Finish Date']), errors='coerce')
    raw = raw[raw['date'].dt.year > 2000]  # Exclude Jan 1900 placeholders

    # Pivot to wide: one row per org+study with milestone dates as columns
    for (org, study), grp in raw.groupby(['Organization','Study Name']):
        dates = {}
        for ms in ['Site Selected','Contract Executed','IRB/EC Approval','SIV','FSFV']:
            r = grp[grp['milestone_clean']==ms]['date'].dropna()
            if len(r): dates[ms] = r.min()
        # Calculate gaps
        def gap(a, b):
            if a in dates and b in dates:
                g = (dates[b] - dates[a]).days
                return g if g >= 0 else None
            return None
